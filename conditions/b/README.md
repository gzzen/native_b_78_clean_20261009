# Condition B-v73 (additive baseline boundary)

B-v3 is constructed as **Condition A plus contrastive-grounding components**.
`conditions/b/runner.py` imports `conditions.a.runner`, reuses A's complete
solver prompt, capsule grouping, workspace/execution substrate, and graded
compliance audit, and then adds B's prompt extension, grounding schema, and
non-blocking optional execution consistency audit. B does not independently copy or
reimplement the A baseline. A malformed or absent optional B audit is recorded
as a B component status and never erases a valid A candidate.

Every capsule attempt owns a separate workspace-local `tmp/` tree. The
controller exports that tree through `TMPDIR`, `TMP`, and `TEMP` (plus common
scientific-library cache variables); literal shared `/tmp` and `/var/tmp`
remain forbidden. Concurrent capsules therefore cannot observe or overwrite
one another's temporary artifacts.

In compact form:

```text
B = import(A) + contrastive grounding + execution consistency
```

It performs the A-compatible baseline, records 2–3 evidence-backed semantic
interpretations only for genuine ambiguity, locks one (or marks the question
unresolved), and the runner may inspect a compact post-execution record if one
exists. Existing frozen results generated by the former
standalone implementation remain historical artifacts and are not relabeled as
results from this composed implementation.

Run the full 19-capsule / 78-question generation with:

```bash
python conditions/b/runner.py --execute
```

Generation uses OpenCode v2 with `deepseek/deepseek-flash`, high reasoning
effort and 2 workers by default. Each capsule gets a private OpenCode server
inside its own network-none container. See [OpenCode deployment](../../OPENCODE_DEEPSEEK.md).

Run an explicitly preregistered diagnostic subset with a fresh run root and
output paths:

```bash
python conditions/b/runner.py --execute --short-ids bix-10,bix-29
```
